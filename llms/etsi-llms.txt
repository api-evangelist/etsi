# ETSI — European Telecommunications Standards Institute

> ETSI is a not-for-profit standards development organisation in Sophia Antipolis, France, and one of only three bodies officially recognised by the EU as a European Standards Organisation. It writes the specifications that mobile, fixed, broadcast, IoT and security networks are built from, and it hosts the 3GPP Mobile Competence Centre. Its API posture is unusually open for a standards body: every deliverable is downloadable free without login, and the machine-readable API artefacts are published as BSD-3-Clause OpenAPI on two public GitLab instances that both serve an anonymous REST API. Membership gates participation — drafting, voting, working documents — not publication.

Generated 2026-07-25 by the API Evangelist enrichment pipeline. Method: generated from apis.yml plus the artefacts in this repository and live probes of ETSI's public surfaces.

## What ETSI actually publishes

- [ETSI standards library](https://www.etsi.org/deliver/): every ETSI deliverable, free, no login, superseded versions retained permanently
- [Get standards](https://www.etsi.org/standards/get-standards): browse by technology
- [ETSI Forge GitLab](https://forge.etsi.org/rep/): OpenAPI for ISG MEC, NFV SOL and ISG CIM NGSI-LD — anonymous REST API at `https://forge.etsi.org/rep/api/v4`
- [ETSI Labs GitLab](https://labs.etsi.org/rep/): OpenCAPIF, OpenSlice, Operator Platform, TeraFlowSDN, MEC Sandbox — anonymous REST API at `https://labs.etsi.org/rep/api/v4`
- [Work Programme](https://portal.etsi.org/webapp/WorkProgram/): every work item, its stage and target date — ETSI's de-facto public roadmap
- [Licensing](https://forge.etsi.org/legal-matters): the OpenAPI artefacts are BSD-3-Clause

## Conventions an agent needs to know

- **Three convention families, and they disagree.** NFV SOL uses opaque-marker pagination plus RFC 8288 `Link` headers and `application/problem+json`; ISG MEC uses `ProblemDetails` with attribute-based filtering; the OpenSlice TM Forum set uses `offset`/`limit`, a `fields` parameter and the TM Forum `Error` envelope. Do not assume one house style.
- **No idempotency.** Zero occurrences of an idempotency key across all 112 documents. Do not blind-retry writes.
- **No rate-limit contract.** 429 is declared by 193 operations but no `RateLimit` or `Retry-After` header contract accompanies it.
- **Loopback `servers[]` is by design.** Most ETSI documents describe a standardised interface, not a hosted service, so `{apiRoot}` and `127.0.0.1` appear in `servers[]`. The only production host in the corpus is `https://portal.openslice.eu/tmf-api`.
- **Events are webhooks, not AsyncAPI.** 171 notification types across three families, all modelled inside OpenAPI as a subscription resource plus an HTTP callback. ETSI publishes no AsyncAPI.
- **Versioning is the deliverable version.** `V<major>.<technical>.<editorial>`, mirrored as the git tag on ETSI Forge. Only the major version appears in the URI path.

## Security and trust

- [Coordinated Vulnerability Disclosure](https://www.etsi.org/standards/coordinated-vulnerability-disclosure/) — report flaws in ETSI *standards* (not vendor implementations) to `ETSI_CVD@etsi.org` or the online form. Anonymous reporting supported, hall of fame available, no bounty (ETSI is not-for-profit).
- No RFC 9116 `security.txt` on any ETSI host.
- No SOC 2 / ISO 27001 / PCI DSS attestation published for ETSI's own web estate.
- `etsi.org`: TLS 1.3, HSTS on www, SPF and DMARC at `p=reject`, CAA records set, DNSSEC not enabled.
